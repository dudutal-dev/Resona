# Resona — אפליקציית תדרים ומסעות

אפליקציית ווב (PWA) לשימוש אישי שמנגנת **מלודיות אמיתיות המולחנות סביב תדר יעד מוצהר** —
סולפג׳יו, ביינאורל/איזוכרוני וכוונון 432Hz — עם מיקסר שכבות, פריסטים שמורים ומסעות מודרכים
רב-יומיים.

הכול רץ בדפדפן: **בלי חשבון, בלי תשלום, בלי שרת, בלי מסד נתונים.** כל הנתונים נשמרים
ב-`localStorage` של המכשיר.

---

## הרעיון המרכזי — "עיגון" (Anchoring)

הפער שהאפליקציה נועדה לסגור הוא שמוזיקת רקע אמביינטית בדרך כלל *אין לה* תדר מוצהר, ומחוללי
תדרים בדרך כלל *אינם מוזיקה*. כאן התדר הנבחר אינו טון שמונח ליד המוזיקה — הוא **תדר היסוד
שממנו המוזיקה נגזרת**:

```ts
const rootFrequency = 528                                  // Hz
const scaleRatios   = [1, 9/8, 5/4, 4/3, 3/2, 5/3, 15/8]   // אינטונציה טהורה
const scale         = scaleRatios.map(r => rootFrequency * r)
```

כל תו שהסינתיסייזר מנגן הוא `root × יחס הרמוני טהור × 2^אוקטבה` — ולכן כל צליל באפליקציה
הוא יחס הרמוני שלם של התדר שבחרת. זה נאכף בבדיקות יחידה
([`src/audio/scale.test.ts`](src/audio/scale.test.ts)), שמוודאות שאין ולו פיץ׳ אחד בסולם
שאינו מכפלה הרמונית של השורש.

המלודיה נוצרת בזמן אמת דרך הליכת Markov משוקללת על דרגות הסולם, עם משך, אוקטבה, עוצמה
והסתברות שמשתנים בכל תו. **אין קובץ, אין לופ, ואין שתי האזנות זהות** — פתרון ישיר לבעיית
"אחרי שבועיים אני מכיר כל רצועה בעל פה".

## הפעלה

```bash
npm install
npm run dev        # שרת פיתוח
npm run build      # בילד לפרודקשן ל-dist/
npm run preview    # תצוגה מקדימה של הבילד (כאן ה-Service Worker פעיל)
npm test           # בדיקות יחידה
npm run audit      # בדיקות על אפליקציה רצה (אודיו אמיתי, מסכים אמיתיים)
npm run icons      # רינדור מחדש של אייקוני האפליקציה
```

### `npm run audit`

בדיקות היחידה מכסות את מה שאפשר להכריע מתוך נתונים — חשבון הסולמות, הקטלוג ובונה
המסעות. כל השאר קיים רק כשהאפליקציה מנגנת, ולכן נבדק כאן: הרצה מרימה שרת פיתוח נקי,
פותחת דפדפן, ומודדת.

| בדיקה | מה היא מגינה עליו |
| --- | --- |
| `levels` | רמת היציאה של כל סגנון, והפער ביניהם — סגנון שנפל 11dB כבר קרה פעם |
| `anchor` | כל תו שמנוגן הוא יחס טהור של תדר היעד, נתפס בנקודת ההשמעה |
| `groove` | כל מנוע מועדון מנגן את התבנית שלו — ספירה במקור, לא בספקטרום |
| `recovery` | context שנקטע חוזר, ומשמיע — והתקלה נרשמת ביומן |
| `route` | זרם יציאה מת נבנה מחדש במקום שיסמכו עליו (הבאג של שיחת הטלפון) |
| `screens` | 66 רינדורים: 11 מסכים × 3 ערכות × 2 שפות |

`npm run audit -- levels groove` מריץ רק את מה שביקשת. יציאה 1 אם משהו נכשל, כדי שזה
יוכל לשמש שער לפני שחרור. הרצה מלאה לוקחת בערך ארבע דקות, והיא דורשת פורט פנוי —
שרת שכבר רץ נדחה במקום להיות ממוחזר, כי שרת ותיק צובר hot reloads ובודק אז מודול
שאיש לא מרנדר.

### פריסה

**GitHub Pages** — האפליקציה הבנויה יושבת ב-`docs/` בענף `main` ומוגשת מ:
`https://dudutal-dev.github.io/Resona/`

הפעלה חד-פעמית: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/docs` → Save**.
אחרי שינוי בקוד: `npm run build:pages`, ואז commit ל-`docs/` מעדכן את האתר.

**קובץ בודד** — `npm run build:single` יוצר `dist-single/resona.html`: קובץ אחד עם הכול בפנים,
שרץ בלחיצה כפולה בלי שרת ובלי התקנה.

**אחסון סטטי אחר** — להעלות את תוכן `dist/`. ה-`base` הוא `./` והניתוב מבוסס hash, ולכן זה עובד
גם מתת-תיקייה וגם ללא כללי rewrite.

## עיצוב

ממשק כהה עם רקע אורורה נע, כרטיסי זכוכית, זוהר רך — ו**ויזואליזציה רדיאלית חיה** שנשענת על
ה-Analyser של מנוע האודיו (ספקטרום רדיאלי, טבעת גל, גרעין נושם, טבעות פעימה). כל הממשק
מתכוונן לגוון של התדר הנבחר דרך משתנה CSS יחיד (`--h`), כך שהמסך משנה צבע יחד עם הצליל.

RTL מלא, רספונסיבי ממובייל ועד דסקטופ, מצב בהיר/כהה, ואפשרות "הפחתת תנועה".

## שקיפות

לכל תדר מוצמדת רמת ביסוס, ומשפט השקיפות מוצג לצידו בכל מקום שבו הוא מופיע:

- `traditional` → *"מבוסס מסורת ואמונה תרבותית ואינו נתמך בראיות מדעיות קליניות."*
- `research_backed_partial` → *"קיימות ראיות מחקריות חלקיות ולא עקביות."*

Resona הוא כלי להרפיה והאזנה. אינו מכשיר רפואי, אינו מאבחן ואינו מטפל, ואינו תחליף לייעוץ
מקצועי.

## החלטות מימוש ששונות מהאפיון

האפיון מומש במלואו; חמש נקודות מומשו אחרת מהמוצע בו, וזו הסיבה לכל אחת:

1. **סאונד הסביבה מסונתז ולא מקובץ.** האפיון הציע קבצי MP3/OGG חופשיים. סינתזה מרעש מסונן
   נותנת לופ חלק לחלוטין (אין נקודת לופ בכלל), מבטלת את שאלת הרישוי, שומרת על התקנה קטנה,
   ועובדת אופליין כבר מהטעינה הראשונה. **תמיכת הקבצים נשמרה** — כל קובץ שנרשם ב-
   [`public/audio/ambience/manifest.json`](public/audio/ambience/README.md) מופיע בבורר לצד
   האפשרויות המסונתזות ומנוגן ב-`Tone.Player` עם לופ ו-fade.

2. **`TimerMode` הורחב ב-`custom`.** ימי המסעות מכתיבים משכים מדויקים (20, 25, 45, 90 דקות)
   שאינם ניתנים לביטוי בסט הקבוע; עיגול שקט של משך שנקבע היה מציג את לוח הזמנים בצורה לא
   נכונה.

3. **`Preset` נושא גם `config` מלא** לצד שדה `layers` שבסכמת האפיון — כדי שטעינת פריסט תשחזר
   גם קצב פעימה, אופן השמעה, צפיפות וסאונד סביבה, ולא רק תדר ועוצמה.

4. **אין זיהוי אוזניות.** אין API בדפדפן שמאפשר זאת. במקום לנחש, ברירת המחדל היא איזוכרוני
   (שעובד ברמקולים), והמשתמש מקבל הסבר חד-פעמי מתי ביינאורל דורש אוזניות ובוחר בעצמו.

5. **ניתוב hash במקום ספריית ניתוב**, ואייקונים שמרונדרים בסקריפט
   ([`scripts/generate-icons.mjs`](scripts/generate-icons.mjs)) במקום תלות גרפית — שניהם
   בהיקף שלא מצדיק תלות נוספת, ושניהם עובדים בפריסה סטטית מכל תת-נתיב.

6. **אין נגינה ברקע אחרי יציאה מהדפדפן בטלפון.** דפדפני מובייל — ובמיוחד ספארי ב-iOS — משהים
   את ה-`AudioContext` כשהדף עובר לרקע, ואין ל-Web Audio API דרך לבקש חריגה. במקום להסתמך על
   האק שעובד חלקית, מומשו הדברים שכן פועלים: Media Session API לפקדי מסך הנעילה, חידוש אוטומטי
   של הנגינה בחזרה לדף, ו-Screen Wake Lock שמונע מהמסך לכבות באמצע האזנה. ניתוב למכשיר חיצוני
   נעשה דרך בורר ה-AirPlay של ספארי היכן שהוא קיים, ואחרת דרך בקרת השמע של מערכת ההפעלה — שחלה
   ממילא על כל צליל שהדף מפיק.

בנוסף, הפרויקט נבנה בשורש הריפו (ולא בתת-תיקייה `frequency-app/`), מכיוון שהריפו כולו הוא
האפליקציה.

## הרחבה

- **תדרים**: הוספת רשומה ל-`src/data/frequencies.json` (נדרשים `id`, `type`, `label`,
  `trust`, `info`, `hue`, ו-`hz` או `range`).
- **מסעות**: הוספת רשומה ל-`src/data/journeys.json`. הבדיקות מוודאות שכל יום מצביע על תדר
  קיים ושאורך הלו״ז תואם למספר הימים המוצהר.
